# 架构概览

## 组件与角色

OutpostNet 由三个核心组件构成，协同实现从单机服务代理到跨区域隧道的完整链路。

```
┌─────────────────────────────────────────────────────────────────┐
│  区域 A（边缘节点）                                               │
│                                                                  │
│  ┌─────────────┐   Unix socket   ┌──────────────────────────┐   │
│  │  Application│◄───────────────►│  outpostnet-sidecar      │   │
│  │  (port 8080)│                 │  - 导出本地服务           │   │
│  └─────────────┘                 │  - 导入远程服务为本地端口  │   │
│                                  └──────────────┬───────────┘   │
│                                                 │ Unix socket   │
│                                  ┌──────────────▼───────────┐   │
│                                  │  outpostnet-server       │   │
│                                  │  - 服务注册与路由         │   │
│                                  │  - 多 sidecar 复用        │   │
│                                  └──────────────┬───────────┘   │
│                                                 │               │
│                                  ┌──────────────▼───────────┐   │
│                                  │  outpostnet-agent        │   │
│                                  │  - QUIC 隧道管理          │   │
│                                  │  - 跨区域路由             │   │
│                                  └──────────────┬───────────┘   │
└─────────────────────────────────────────────────┼───────────────┘
                                                  │ QUIC (TLS)
┌─────────────────────────────────────────────────┼───────────────┐
│  区域 B（云端或另一边缘节点）                      │               │
│                                  ┌──────────────▼───────────┐   │
│                                  │  outpostnet-agent        │   │
│                                  │  - QUIC 隧道对端          │   │
│                                  └──────────────┬───────────┘   │
│                                                 │               │
│  ┌─────────────┐   本地端口      ┌──────────────▼───────────┐   │
│  │  Consumer   │◄───────────────►│  outpostnet-sidecar      │   │
│  │  Application│                 │  - 导入区域 A 的服务      │   │
│  └─────────────┘                 └──────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
```

## 组件职责

### outpostnet-server

- 在每台主机上运行一个实例
- 通过 Unix domain socket 接受 sidecar 连接
- 维护服务注册表：哪个 sidecar 导出了哪些服务
- 将连接请求路由到对应的 sidecar
- 通过心跳检测并清理失效连接

### outpostnet-sidecar

- 与本机 server 建立持久连接
- **导出（Export）**：向 server 注册本地服务，接受来自其他 sidecar 或 agent 的连接，将流量转发给本地应用
- **导入（Import）**：在本机监听端口，将应用的连接请求通过 server 路由到远端服务
- 同时支持 TCP 和 UDP

### outpostnet-agent

- 每个区域运行一个实例
- 通过 QUIC 协议与其他区域的 agent 建立加密隧道
- 支持 server/client 两种角色，决定谁主动发起连接
- **导出**：将本区域的服务通告给其他区域
- **导入**：将其他区域的服务映射为本地可访问的端口或地址
- **中继**：作为流量中转节点，支持多跳场景（如 far-edge → relay → cloud）
- 配置持久化支持 agent 重启后自动恢复

## 数据流

### 场景一：单机本地路由

```
App-A → sidecar-A → server → sidecar-B → App-B
```

两个应用在同一主机上，通过 server 互相访问对方的服务。

### 场景二：跨区域访问

```
App-B (区域 B) → sidecar-B → server-B → agent-B
               ────── QUIC tunnel ──────
               agent-A → server-A → sidecar-A → App-A (区域 A)
```

应用 B 访问区域 A 的服务，流量经过 QUIC 隧道加密传输。

### 场景三：多跳中继

```
App-C (区域 C) → agent-C ──→ agent-B (中继) ──→ agent-A → App-A (区域 A)
```

区域 C 无法直接访问区域 A，通过区域 B 的 agent 做多跳中继（最多 5 跳）。

## 协议层

### 内部协议（server ↔ sidecar）

使用基于 Unix socket 的自定义二进制协议：

- **帧格式**：长度前缀 + 消息类型 + Payload
- **消息类型**：Handshake / Register / Connect / OpenStream / Data / StreamClose / Heartbeat
- **流模型**：32-bit stream ID，控制流（ID=0）用于握手和注册，数据流用于实际服务数据
- **缓冲区**：每个流 32KB

### 隧道协议（agent ↔ agent）

- 基于 QUIC（实现为 quic-go）
- 支持 TLS 加密，可配置证书或使用自签证书
- 共享 token 认证（可选）
- 多流复用，每个 QUIC 连接承载多个服务流

## 部署模式

### Standalone（直接运行）

适用于非容器或非 K8s 环境，如：

- 裸机边缘节点
- 轻量虚拟机
- Docker 容器（手动配置）

每个组件作为独立进程运行，通过配置文件互联。

### Kubernetes（自动注入）

适用于 K8s 集群，使用 `outpostnet-controller`：

- MutatingWebhook 根据 Pod 注解自动注入 sidecar 容器
- Pod 注解 `outpostnet.io/inject: "true"` 触发注入
- 通过注解声明导出和导入服务，无需手写 sidecar 配置

## 关键设计决策

| 决策 | 原因 |
|------|------|
| Unix domain socket（server ↔ sidecar） | 同机通信性能更高，无需网络栈开销 |
| QUIC（agent ↔ agent） | 原生多路复用、内置 TLS、移动网络下抖动恢复 |
| agent 配置持久化 | 边缘节点网络不稳定，重启后自动恢复隧道 |
| sidecar 模式（而非 iptables 劫持） | 更容易排查，不依赖内核权限，跨平台 |
